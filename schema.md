# Data model (PostgreSQL)

All identifiers are UUIDs (generated by the API or `gen_random_uuid()`). All
timestamps are `timestamptz` in UTC. Monetary values are signed `bigint`
minor units; the suggested scale is `credit_micros` (1 credit = 1,000,000
micros). Token counts and byte counts are non-negative `bigint`/`integer`.
Historical rows are append-only unless a field is explicitly marked mutable.

## Core tables

### `users`

| Column | Type | Constraints / purpose |
| --- | --- | --- |
| `id` | uuid | PK |
| `email` | citext | UNIQUE, normalized login address |
| `password_hash` | text | Argon2id encoded hash; never log or return |
| `role` | text | `user` or `admin`, default `user` |
| `status` | text | `active`, `suspended`, `deleted`; API auth rejects non-active |
| `invited_by` | uuid | nullable FK `users.id` |
| `created_at`, `updated_at`, `last_login_at` | timestamptz | audit timestamps |

### `web_sessions`

| Column | Type | Constraints / purpose |
| --- | --- | --- |
| `id` | uuid | PK, never exposed as a bearer token |
| `user_id` | uuid | FK `users.id` ON DELETE CASCADE |
| `token_hash` | bytea | UNIQUE hash of random session token |
| `csrf_hash` | bytea | hash of CSRF token for cookie mutations |
| `expires_at`, `created_at`, `last_seen_at` | timestamptz | expiry/rotation |
| `ip_hash`, `user_agent_hash` | bytea | optional abuse diagnostics, not raw PII |

Session cookies are Secure, HttpOnly and SameSite=Lax (or Strict where the
console permits). Rotate the token after login and privilege changes.

### `invitations`

| Column | Type | Constraints / purpose |
| --- | --- | --- |
| `id` | uuid | PK |
| `code_hash` | bytea | UNIQUE HMAC/SHA-256 of one-time code |
| `created_by` | uuid | FK admin user |
| `max_uses`, `used_count` | integer | `used_count <= max_uses` |
| `expires_at`, `created_at` | timestamptz | validity window |
| `disabled_at` | timestamptz | nullable |

The `settings` table has `registration_invite_required boolean`; consume an
invitation in the same transaction as user creation.

### `device_keys`

| Column | Type | Constraints / purpose |
| --- | --- | --- |
| `id` | uuid | PK |
| `user_id` | uuid | FK `users.id` ON DELETE CASCADE |
| `key_hash` | bytea | UNIQUE HMAC-SHA-256 using a server pepper |
| `display_prefix` | text | e.g. `vv_live_7ab3`; safe to show in UI |
| `label` | text | user-provided device label, length limited |
| `created_at`, `last_used_at` | timestamptz | activity timestamps |
| `expires_at`, `revoked_at` | timestamptz | nullable; revoked is terminal |
| `rpm_limit`, `concurrency_limit` | integer | per-key override, nullable means policy default |

The plaintext format is `vv_live_` plus at least 32 random URL-safe bytes. It
is returned once over HTTPS from `POST /api/v1/keys`; retrieval is impossible.
Hash lookup uses a keyed HMAC so a database dump is not an offline key check.

### `model_aliases`

| Column | Type | Constraints / purpose |
| --- | --- | --- |
| `alias` | text | PK, e.g. `vv-dialogue`, `vv-fast` |
| `provider` | text | internal provider name consumed by LiteLLM |
| `provider_model` | text | private model identifier |
| `enabled` | boolean | public aliases only when true |
| `max_input_tokens`, `max_output_tokens` | integer | hard policy caps |
| `timeout_ms`, `rpm_limit`, `concurrency_limit` | integer | route policy |
| `price_version_id` | uuid | FK `pricing_versions.id` |
| `created_at`, `updated_at` | timestamptz | mutable routing metadata |

Clients send only `alias`; `provider_model` and provider credentials never
leave the private network.

### `providers`

The production database stores one row per managed upstream account. The
browser can edit routing metadata, but never reads the secret back.

| Column | Type | Constraints / purpose |
| --- | --- | --- |
| `id` | uuid | PK |
| `name` | text | admin label, length limited |
| `base_url` | text | credential-free HTTPS API root |
| `api_key_ciphertext` | bytea/text | AES-GCM ciphertext using a key derived from the server secret; never return plaintext |
| `default_model` | text | optional provider model fallback |
| `enabled` | boolean | disabled providers reject new routed calls |
| `last_checked_at`, `last_check_status` | timestamptz/text | non-billing health probe result |
| `created_at`, `updated_at` | timestamptz | audit timestamps |

`model_aliases.provider_id` references this table. The current JSON Demo uses
the same shape and encrypts managed API keys with AES-256-GCM. In production,
move ciphertext and audit data to PostgreSQL/KMS-backed secrets before adding
many operators or payment volume.

### `pricing_versions`

| Column | Type | Constraints / purpose |
| --- | --- | --- |
| `id` | uuid | PK |
| `input_micros_per_1k` | bigint | >= 0 |
| `output_micros_per_1k` | bigint | >= 0 |
| `cached_input_micros_per_1k` | bigint | >= 0 |
| `effective_from`, `effective_to` | timestamptz | immutable price window |
| `created_by`, `created_at` | uuid/timestamptz | audit |

Prices are copied onto usage/ledger metadata at settlement, so changing a
route never changes a past bill.

## Wallet, reservation and usage tables

### `wallet_accounts`

One row per user (`user_id` UNIQUE). `available_micros` is the spendable
balance; `reserved_micros` is an informational aggregate. Both are updated
under row lock and must never become negative.

### `wallet_ledger`

Append-only double-entry-like entries:

| Column | Type | Purpose |
| --- | --- | --- |
| `id` | uuid PK | ledger entry |
| `user_id` | uuid FK | account owner |
| `kind` | text | `admin_topup`, `redeem`, `reservation`, `settlement`, `release`, `adjustment` |
| `amount_micros` | bigint | signed; positive adds available credit |
| `request_id`, `reservation_id` | uuid nullable | idempotent linkage |
| `balance_after_micros` | bigint | resulting available balance |
| `metadata` | jsonb | alias, provider, price version, reason; no prompt |
| `created_at`, `created_by` | timestamptz/uuid | audit |

Unique constraints prevent duplicate financial effects, for example
`(reservation_id, kind)` for `reservation`, `settlement` and `release`.

### `billing_reservations`

| Column | Type | Purpose |
| --- | --- | --- |
| `id` | uuid PK | reservation ID |
| `user_id`, `request_id` | uuid | both indexed; request FK |
| `reserved_micros` | bigint | calculated from route ceiling |
| `settled_micros` | bigint nullable | actual bill at completion |
| `status` | text | `reserved`, `settled`, `released`, `expired` |
| `expires_at`, `created_at`, `settled_at` | timestamptz | lease and audit |

### `requests`

One row for every API call, including rejected calls when useful for abuse
metrics. Do not store raw messages. Recommended columns:

`id` (UUID/request ID), `user_id`, `device_key_id`, `idempotency_key` (nullable,
unique per user), `model_alias`, `status` (`accepted`, `in_progress`,
`completed`, `failed`, `usage_pending`, `rejected`), `http_status`,
`provider_request_id`, `reservation_id`, `input_bytes`, `output_bytes`,
`latency_ms`, `error_code`, `error_class`, `created_at`, `completed_at`.

Store a SHA-256 fingerprint of the normalized request only when needed for
idempotency/debugging; it is not a transcript.

### `request_usage`

One-to-one with `requests` after provider completion:

`request_id`, `prompt_tokens`, `completion_tokens`, `cached_prompt_tokens`,
`total_tokens`, `input_cost_micros`, `output_cost_micros`,
`cached_input_cost_micros`, `total_cost_micros`, `price_version_id`,
`provider_reported` (boolean), `created_at`.

## Administration and redemption

### `redeem_codes`

Store `code_hash`, a safe `display_prefix`, `value_micros`, `max_uses`,
`used_count`, `expires_at`, `disabled_at`, `created_by`, `created_at`.
Redemption locks the row, increments usage and creates one `wallet_ledger`
entry with a unique `(redeem_code_id, user_id)` (or a separate redemption ID
when multiple uses are allowed).

### `admin_audit_log`

Append-only record of actor, action, target type/id, request ID, timestamp,
IP hash and redacted JSON metadata. Examples: suspend user, revoke key,
manual top-up, create redeem code, change model price, toggle invitations.

### `settings`

Small key/value table for invite gate, persisted runtime demo mode and global
policy defaults. Sensitive secrets are not stored here; use deployment secret
injection.

## Atomic reservation algorithm

The API computes a worst-case ceiling before contacting LiteLLM:

```sql
BEGIN;
SELECT available_micros
  FROM wallet_accounts
 WHERE user_id = $1
 FOR UPDATE;

-- $2 = calculated reservation ceiling
UPDATE wallet_accounts
   SET available_micros = available_micros - $2,
       reserved_micros = reserved_micros + $2,
       updated_at = now()
 WHERE user_id = $1
   AND available_micros >= $2;
-- require one updated row, otherwise return 402 insufficient_balance

INSERT INTO requests (..., status, idempotency_key) VALUES (..., 'in_progress', $3);
INSERT INTO billing_reservations (..., reserved_micros, status)
  VALUES (..., $2, 'reserved');
INSERT INTO wallet_ledger (..., kind, amount_micros)
  VALUES (..., 'reservation', -$2);
COMMIT;
```

At settlement, lock the same wallet and reservation. Debit the actual cost,
release `reserved - actual`, append `settlement` and (when positive) `release`
entries, and mark the reservation `settled` exactly once. If the provider
fails, append a `release` entry for the full reservation and mark `released`.
The unique reservation constraints make retries harmless.

## Redis keys and limits

- `vv:rl:key:{key_id}:{minute}` and `vv:rl:user:{user_id}:{minute}`:
  atomic Lua increment with TTL for RPM.
- `vv:concurrency:key:{key_id}` and `vv:concurrency:user:{user_id}`:
  semaphore counters; leases include request ID and a TTL.
- `vv:idem:{user_id}:{idempotency_key}`:
  short-lived lock/result pointer. The durable source of truth remains
  `requests.idempotency_key` in PostgreSQL.
